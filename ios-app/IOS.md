# iOS app (TestFlight)

This folder is a small native iOS shell, built with Capacitor, that opens the
live site (`https://ech-technicalsolutions.com/Trips/`) full screen. Nothing in
it is loaded by the website, and the website keeps deploying exactly as before.

Because the app loads the live site, **every merged PR shows up in the app
automatically**. You only rebuild in Xcode to renew the TestFlight build
(builds expire after 90 days) or when something native changes.

Settings worth knowing:

| | |
|---|---|
| Bundle ID | `com.erikhardin.trips` |
| Live URL | `server.url` in `capacitor.config.json` |
| No connection | opens the cached site (see *Offline* below); `www/offline.html` only on a phone that has never loaded it |
| App icon | regenerated by `generate_icons.py` in the repo root |

Google sign-in runs natively in the app (Google blocks its sign-in page in
embedded app views) via `@capgo/capacitor-social-login`, then hands the Google
ID token to Firebase. The iOS client ID comes from the iOS app registered in
the Firebase console (bundle ID `com.erikhardin.trips`); its
`REVERSED_CLIENT_ID` is the URL scheme in `ios/App/App/Info.plist`. The app
does **not** need `GoogleService-Info.plist`.

Sign in with Apple uses the same plugin. Apple's native sheet returns an ID
token, which the site hands to Firebase with a nonce. It needs the **Sign in
with Apple** capability on the App target: Xcode → **Signing & Capabilities** →
**+ Capability** → *Sign in with Apple*. `ios/App/App/App.entitlements` is
committed with this capability (and Push, below) already in it.
`providers.apple` is turned on in `capacitor.config.json`. Run
`npx cap sync ios` after pulling.

## Offline

The site's service worker (`sw.js`) caches the app shell, and the page keeps the
last trips it saw (`OfflineStore`), so with no signal the app still opens to
your trips, with the offline banner. WKWebView only runs a service worker for
**App-Bound Domains**, so `Info.plist` lists `ech-technicalsolutions.com` under
`WKAppBoundDomains` and `capacitor.config.json` sets
`ios.limitsNavigationsToAppBoundDomains`. This is native: it starts working with
the first TestFlight build that includes it, after the app has been opened once
with a connection.

If that build misbehaves (a blank screen, sign-in or the native bridge not
working), remove `limitsNavigationsToAppBoundDomains` from
`capacitor.config.json`, `npx cap sync ios` and rebuild — the app goes back to
showing `offline.html` when there's no connection.

## Push notifications

The app registers for iOS push via `@capacitor/push-notifications`; the site
saves each device's token to Firebase and the Worker sends pushes directly to
APNs. `AppDelegate.swift` forwards the device token to the plugin,
`Info.plist` turns on the *remote-notification* background mode, and
`App.entitlements` carries `aps-environment` (Xcode switches it to production
when you archive for TestFlight).

One-time setup:

1. If `git pull` refuses because a local, uncommitted `App.entitlements`
   would be overwritten, delete the local copy and pull again — the committed
   one already includes Sign in with Apple.
2. Xcode → App target → **Signing & Capabilities**: confirm **Push
   Notifications** and **Sign in with Apple** both appear (they come from the
   entitlements file; if not, **+ Capability** → *Push Notifications*).
3. developer.apple.com → **Certificates, IDs & Profiles** → **Keys** → **+**
   → name it "Trips APNs", tick **Apple Push Notifications service (APNs)**
   → Continue → Register → **Download** the `.p8` (you only get one chance).
   Note the **Key ID** and your **Team ID** (top-right of the page).
4. Add the key to the Worker as secrets (Cloudflare dashboard → Workers →
   `hardin-trips-ai` → Settings → Variables and Secrets) — see `DEPLOY.md`.
5. `npm install`, `npx cap sync ios`, bump **Build** on both targets, and
   Archive → Distribute a new TestFlight build. Push is native, so it only
   works once that build is installed.

## One-time setup (on the Mac)

1. Make sure Xcode is current (App Store → Updates). Capacitor 8 needs a
   recent Xcode.
2. Open Xcode once and let it install its components.
3. Xcode → Settings → Accounts → **+** → add your Apple ID. Your developer
   team should appear under it.
4. Install Node.js 22 or later (LTS) from nodejs.org.

## Build and run on your iPhone

```bash
git clone https://github.com/ErikHardin/Trips.git
cd Trips/ios-app
npm install
npx cap sync ios        # also run this after pulling changes to ios-app/
npx cap open ios        # opens the project in Xcode
```

In Xcode:

1. Select the **App** target → **Signing & Capabilities** → Team: your team.
   Leave "Automatically manage signing" on.
2. Plug in your iPhone and pick it as the run destination at the top.
3. Press ▶. The first time, the phone asks you to turn on **Developer Mode**
   (Settings → Privacy & Security → Developer Mode), which needs a restart.

The first build downloads the Capacitor Swift package, so it takes a few
minutes.

## Upload to TestFlight

1. appstoreconnect.apple.com → **Apps** → **+** → **New App**: platform iOS,
   name "Hardin Trips", bundle ID `com.erikhardin.trips`, any SKU (for example
   `hardin-trips`).
2. In Xcode set the run destination to **Any iOS Device (arm64)**, then
   **Product → Archive**.
3. In the Organizer window that opens: **Distribute App → App Store Connect →
   Distribute**.
4. Wait 10–30 minutes for the build to finish processing (App Store Connect →
   your app → **TestFlight**). The encryption question is already answered in
   `Info.plist`.

## Invite family

1. App Store Connect → **Users and Access** → **+** → their Apple ID email,
   role **Developer** or **Marketing**.
2. Once they accept, add them to the **Internal Testing** group on the
   TestFlight tab. Internal testing needs no Apple review.
3. They install **TestFlight** from the App Store and tap **Install**.

## Every ~85 days

TestFlight builds expire after 90 days. To renew: in Xcode bump **Build**
(General → Identity) on **both** the **App** and **UpcomingWidget** targets —
they must match — then Archive → Distribute again. Testers get the new build
automatically.

### Notification buttons

Activity reminders and leave-by alerts carry **Directions** (Apple Maps
driving directions to the activity) and **Mute reminders** (same as its 🔕
bell). Long-press or pull down the notification to see them. The worker sends
`aps.category = "ACTIVITY"`; `AppDelegate.swift` registers that category, so
the buttons appear only with a build that includes it — older builds show the
same notification without buttons.

## Widgets

`ios/App/UpcomingWidget/` is a WidgetKit extension with two widgets, both
reading the Worker. Anyone with the TestFlight build can add them: long-press
the home screen → **+** → Hardin Trips.

- **Upcoming Trips** (`UpcomingWidget.swift`): the native version of
  `widget-upcoming.js` — trip countdowns + bookings still to make.
- **Today** (`TodayWidget.swift`): on a trip day, the city and the activities
  still ahead (each drops off 30 minutes after it starts); between trips, a
  countdown to the next one. Reads `/widget-data` with the phone's date.

A new widget file must be added to the **UpcomingWidget** target (Xcode does
this when you create it there; the project file isn't folder-synced).

Widgets are compiled into the build, so a change to one ships with the next
TestFlight upload rather than with the website. iOS decides when they refresh
(roughly hourly); tapping one opens the app.

Signing: both targets need your Team under **Signing & Capabilities**. If
`git pull` complains about local changes to `project.pbxproj`, run
`git checkout -- ios/App/App.xcodeproj/project.pbxproj`, pull again, and
re-pick the Team on both targets.
